name: Ctrl+C breaks a running program and CONT resumes it
# README: "CONT — Continue after `STOP` or Ctrl+C break (immediate mode only)"
#
# The counter is what makes the resume meaningful: if CONT restarted the
# program rather than continuing it, the loop would run its full count again
# and A would be reported from a fresh start.
#
# A GOTO loop rather than FOR/NEXT on purpose. Resuming inside a FOR loop does
# not work — the frame lives on the hardware stack, which is reset on the way
# back to the prompt — and whether that should be fixed is still open, see
# tests/FINDINGS.md#cont-cannot-resume-inside-a-for-loop. Using FOR here would
# tangle that undecided question into a case about Ctrl+C.
#
# 3000 rather than a rounder 30000: the loop is interpreted, and the longer
# bound does not finish inside the default 20 s step timeout. The count only
# has to outlast the Ctrl+C, so there is nothing to gain from a bigger one.
mode: basic

> 10 A = A + 1
> 20 IF A < 3000 THEN GOTO 10
> 30 PRINT "REACHED";A
> RUN
< \x03
~ ^BREAK IN
> CONT
~ ^REACHED 3000$
